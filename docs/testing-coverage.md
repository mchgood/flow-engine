## 已验证场景

- 编译：Markdown/Mermaid 子集、端点/环/死路/网关区域、重复声明/边、别名、源码坐标和规模限额。
- 契约：参数边界、成功 null/未选/不存在区分、祖先可见性、运行时类型检查和集合防御性复制；泛型输出的编译器负例。
- 调度：依赖就绪、实际并行、节点执行一次、单线程子流程、父子隔离、注册原子性、准入/队列限制、节点/流程超时、中断和关闭。
- Spring：singleton/作用域代理、容器代理实际调用、受限 SpEL、严格 Boolean、匹配冲突和默认边、并发上下文隔离。
- Starter：真实自动发现、配置绑定及覆盖/退让、启动失败、关闭、多文件/多流程与跨来源引用。
- 加载预算：UTF-8 多字节边界、损坏编码、有限读取的超限拒绝、资源数量和累计字节、重叠位置去重、分段行号展开预算、自定义来源不能绕过注册器预算。
- 拦截器：锁外通知、顺序、作用范围、错误码和异常策略。三个原缺陷回归用例在修复前均失败（业务仍调用 1 次），修复后业务调用为 0；另覆盖并行分支失败后停止业务启动。VM 后置异常重复通知用例在修复前出现 2 次，修复后为 1 次。
- 执行树失败：新增 5 个受控回归用例，覆盖父级/子级失败后的嵌套后继、后续子调用、前置钩子和排队子任务；同时验证普通失败等待物理退出、准入容量恢复和其他根执行不受影响。原实现上 4 个副作用断言失败、1 个排队取消用例超时；修复后全部通过，失败后的新业务调用为 0。
- 生成图：原有 36 张固定种子合法 DAG 对照独立结果模型；新增 2000 份固定种子文本变异，接受者能编译，拒绝者携带定义错误码，不泄漏内部解析异常。
- 负载：16 调用者、每人 2000 次父流程调用，共 32000 次父调用/32000 次子调用/128000 次业务节点调用，结果及调用次数独立核对，关闭后所观察 worker 均退出；另有 500 个任务的宽图验证。
- 打包：无项目 parent 的独立应用消费 install 后的 Starter，验证 imports、资源加载、父子执行及关闭自动加载后的显式注册。

本地带 JaCoCo 的负载观察值：P50 0.458 ms、P95 1.393 ms、P99 3.580 ms（Java 17.0.20、8 worker、16 caller、内存任务、每次父流程）。仅用于记录本轮环境，不是稳定吞吐/延迟门槛，不外推真实 I/O 服务容量。

## 重复验证

```bash
mvn -Pproduction-verification,release-artifacts clean install
python3 scripts/check-coverage.py
mvn -f verification/consumer/pom.xml test
```

普通 `mvn verify` 不运行 soak 标记的 3 个用例，适合开发期；交付和 CI 使用 production-verification。质量报告为各模块 target/surefire-reports 及 coverage 模块 target/site/jacoco-aggregate；core 的 target/soak-report.txt 保存观察值。CI 上传这些报告。Javadoc 非缺失类告警视为失败；注释内容和线程语义仍需审阅，不由格式门禁证明。

## 历史与剩余边界

原来的 53 → 73 → 200 → 205 → 259 个测试属于历史增量，本页不将它们的覆盖率作为当前代码证据。当前 291 个 reactor 测试不代表穷尽所有线程交错或所有输入。

- 文本变异是固定、有界语料，没有覆盖率引导 Fuzz 或正式证明。
- 负载核对指定并发和线程退出，没有多日负载、堆分析或 jcstress 的全部竞争验证。
- 没有突变测试和 JMH；真实业务的容量、尾延迟、下游超时和幂等性必须由宿主验证。
- 验证基线为 Java 17 / Spring 7.0.9 / Boot 4.1.1，没有自动承诺其他宿主版本、事务传播或可变业务对象隔离。
