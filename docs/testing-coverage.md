# 代码与测试覆盖审查

## 结论

原有 73 个测试不是完全没有覆盖核心功能，但分布失衡：52 个集中在 Spring 模块的 FlowEngineTest，core 只有 2 个架构测试，Starter 有 18 个，示例有 1 个。部分负向测试只检查抛异常或 succeeded=false，不能证明错误分类正确、失败后未发生业务副作用。

本次补充 127 个用例，总计 200 个，`mvn verify` 全部通过。未发现可复现的新功能缺陷，因此没有修改生产执行逻辑。增加的是独立契约测试、调度边界测试、组合图对照测试和 CI 覆盖率检查。

测试数量按 Surefire 实际执行用例统计：参数化每行计一个；100 次并发求值和每个种子生成的多张图不人为拆成额外“测试数量”。

## 覆盖率证据

使用 JaCoCo 0.8.13 汇总 core、Spring 适配和 Starter 的生产类。所有模块的测试执行数据都会参与，包括其他模块对 core 的调用。示例模块仅贡献执行数据，不计入生产覆盖率分母；测试类和生成 Javadoc 不计入。

| 指标 | 原 73 个用例 | 当前 200 个用例 |
| --- | --- | --- |
| 行覆盖 | 480 / 504，95.24% | 484 / 504，96.03% |
| 分支覆盖 | 525 / 639，82.16% | 575 / 639，89.98% |

| 模块 | 当前行覆盖 | 当前分支覆盖 |
| --- | --- | --- |
| core | 414 / 418，99.04% | 536 / 595，90.08% |
| Spring 适配 | 39 / 42，92.86% | 39 / 44，88.64% |
| Starter | 31 / 44，70.45% | 无可统计字节码分支 |

Starter 的属性 getter 等未执行行仍计入分母，没有通过排除类提高数字。Spring 的条件装配由框架判断，不会全部表现为本项目的字节码分支；它必须由上下文场景断言验证。现有生产代码有多条语句写在同一行，因此行覆盖率尤其不能单独衡量测试质量。

## 可重复执行方式

```bash
mvn verify
python3 scripts/check-coverage.py
```

报告路径：

- `flow-engine-coverage/target/site/jacoco-aggregate/index.html`：聚合 HTML。
- `flow-engine-coverage/target/site/jacoco-aggregate/jacoco.xml`：CI 使用的机器报告。
- 各模块 `target/surefire-reports/`：测试结果与失败详情。

JaCoCo 使用每模块独立执行文件，append=false，防止重复运行累计旧数据。聚合模块排在被测模块之后，避免先生成 core 报告而漏掉 Spring 集成测试对 core 的覆盖。

CI 在 verify 后检查报告与必需模块是否存在，并检查行覆盖率 >=95%、分支覆盖率 >=88%。这些是防退化门槛，不是完整性标准；不能通过降低门槛或排除关键类来规避失败。CI 上传测试与覆盖率报告，保留 14 天。

## 仍未证明的风险

- 固定种子生成的是合法 DAG；尚未进行任意文本的覆盖率引导 Fuzz，也没有系统验证每种非法交叉网关区域。
- 同步器覆盖了指定竞争顺序，不能穷尽关闭、取消、提交、完成的所有线程交错；尚未做 jcstress 或长时间负载/泄漏测试。
- 未进行突变测试，无法用当前结果量化断言对所有错误实现的识别能力。
- 没有 JMH 性能基准，不能给出吞吐量、尾延迟或最大图规模下的成本保证。
- 容器基线仍为 Java 17 / Spring 7.0.9 / Boot 4.1.1；没有据此承诺其他版本兼容。
- 剩余未覆盖行/分支包含防御性错误路径和属性访问器；目前没有为提高数字编写重复实现的 getter 测试。

覆盖率工具行为参考 [JaCoCo 聚合报告说明](https://www.jacoco.org/jacoco/trunk/doc/report-aggregate-mojo.html)。
